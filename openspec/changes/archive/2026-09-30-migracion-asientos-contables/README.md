## Summary

`AsientosContables_Carga.py` — the 666-line pandas script at the repository
root — becomes `app/procesadores/asientos_contables/`, registered under the
key `asientos-contables`, following the `contado_carga` precedent to the
letter. One execution takes one to seven Excel files, one per payment type
(AMEX, DINNERS, MASTERCARD, SAFETYPAY, VISA, IZIPAY, EFECTIVO), and returns
one `resultado_<tipo>_procesado.xlsx` per file.

Verified against the seven real inputs of August 2025: the module reproduces
the seven **historical** outputs (generated by the script on 2025-08-26)
**cell by cell with exact equality** — zero tolerance, in all 20 sheets.

## Exploration

Read all of the script, the seven real inputs (every sheet and header row,
value types per column) and the seven historical outputs.

Findings that changed the work:

- **The closing date is almost always empty, and "today" is the real rule.**
  The script falls back to `datetime.now()`; every historical output carries
  `20250826`, the run day, except one AMEX header with a real `20250701`.
  Kept, with an injectable clock (`AsientosContables(hoy=...)`).
- **Headers differ for the same position.** COMPENSACION's sixth column is
  `OBS`, `Ajuste` (VISA) or `Referencia` (IZIPAY); the closing date is
  `Fecha Cierre` or `Fecha cierre`; IZIPAY has `fecha dia` at 6 and the
  closing date at 7. Columns are read by name with aliases, after `strip()`
  + `casefold()`.
- **Reading by position hid a real bug.** The script adds its helper columns
  (`fecha`, `monto`) *before* checking `len(columns) >= 7`, so on a narrow
  sheet `iloc[:, 6]` read the amount as the closing date. Reading by name
  removes it.
- **The files are heavy in odd ways.** DINNERS is 50.7 MB, 65 MB of it
  embedded drawings, and its card sheet declares 1,048,576 formatted-empty
  rows. EFECTIVO's COMPENSACION has ~711k rows **and its last row has
  data**, so no "stop after N empty rows" heuristic is equivalent to the
  script. Empty rows are skipped one by one.
- **IZIPAY's empty `fecha dia` is not a loss.** 585 of ~900 COMPENSACION rows
  have it empty — including 63 DZ rows from earlier days. It is how the
  operator leaves a row out of the day's entry, so it is not reported.
- **Dead code:** `procesar_por_fecha` is never called and
  `procesar_hoja_ajuste` is defined twice, identically.
- **Tipo detection by sheet names classifies all seven samples.** Six carry a
  sheet named exactly like their type; EFECTIVO has none, but has
  `COMPENSACION` plus a sheet `Efectivo`.

## Decisions

Taken with the user before implementation:

1. One key, one portal window. Contract row `entradas_min=1, entradas_max=7`,
   xlsx only, default size caps.
2. One xlsx per uploaded file; `app.core.empaquetado` decides single vs ZIP.
3. Type detection: exactly one card sheet → that type; more than one →
   `tipo_no_reconocido`; none, `COMPENSACION` present and an `Efectivo`
   sheet or "EFECTIVO" in the name → EFECTIVO; otherwise the script's
   filename-substring rule (so `AMEX.xlsx` without its sheet fails with
   `hoja_faltante: AMEX`); otherwise `tipo_no_reconocido`.
4. Two files of the same type → `tipo_duplicado` (outputs would collide).
5. Any failure fails the whole execution; the script's per-sheet
   `try/except: print` is gone.
6. New closed `motivo` values `hoja_faltante`, `tipo_no_reconocido`,
   `tipo_duplicado`, with classmethods on `ErrorContenido`. The
   `ContextoContenido` shape is unchanged: `hoja_faltante` carries the sheet
   name in `columna`.
7. Closing date falls back to an injectable "today".
8. Columns by name with aliases; missing → `columna_faltante`.
9. Business rules verbatim (see the module docstring for the list of quirks).
10. Silent losses reported in `observaciones.txt` (CRLF, UTF-8, only when
    non-empty) and a `registrar_descartes` log line per file.
11. Descriptor-based `load_workbook(read_only=True, data_only=True)`.

Taken during implementation, and documented in the module:

- **The closing-date column is mandatory** in all three sheet kinds. Every
  sample has it. Falling back to "today" when the *column* is missing would
  silently replace real dates under a renamed header — the exact failure the
  hardening exists to prevent.
- **Where the script crashed, one row is lost and reported.** A RECARGA row
  with an unreadable date (`NaT.strftime`), or any unreadable date in
  IZIPAY's three strict `pd.to_datetime` reads, made the script drop the
  **whole output sheet** with a `print`. Here the row goes to
  `observaciones.txt` as `fecha_invalida`. An unreadable non-empty closing
  date falls back to today (as `errors='coerce'` does elsewhere in the
  script) and is reported as `fecha_cierre_invalida`. None of the seven
  samples hits either case.
- **A number in a date column is an unreadable date.** `pd.to_datetime`
  read it as nanoseconds since 1970 and produced a `19700101` entry. Same
  criterion as `contado_carga`.
- **Pandas emulation, measured rather than assumed.** `groupby().sum()` is
  Kahan-compensated and `Series.sum()` is numpy pairwise; both are
  reproduced and checked against pandas 3.0.6 on 3,003 random cases (zero
  differences). The strings `read_excel` turns into NaN (`"NA"`, `"nan"`,
  `"#N/A"`, …) are honoured.
- **`fin_de_linea = "no_aplica"`** was added to the parity manifest
  contract: these pairs are xlsx-only and writing `CRLF` there would claim
  something nobody observed.

## Implementation

- **`app/procesadores/asientos_contables/modulo.py`** — the processor.
  `validar` reads only header rows (type, sheets, columns, duplicates);
  `procesar` computes every output before writing any, so a later
  `cero_filas` leaves no half-written Excel.
- **`app/core/errores.py`** — `MotivoContenido` alias with the three new
  values and their classmethods.
- **`app/core/contrato.py`**, **`app/registry.py`** — contract row and
  registration (the startup coherence check requires both).
- **`openspec/specs/error-contract/spec.md`** — `contenido` row updated.
- **`pyproject.toml`** — the legacy script is excluded from ruff, like
  `Contado_Carga.py`.
- **`tests/paridad/manifiesto.py`, `manifiesto.toml`** — `no_aplica` line
  ending; seven pairs with provenance.

## Verification

- `tests/test_procesador_asientos_contables.py` — behaviour tests on
  synthetic workbooks saved as extensionless `entrada_N`: every sheet of
  every type, the verbatim quirks, detection, duplicates, missing
  sheet/column, `cero_filas`, the clock, observations and their log line,
  pandas sums, and an HTTP end-to-end test across the `spawn` child
  (two files → ZIP; a duplicate → typed 422).
- `tests/paridad/test_asientos_contables.py` — seven pairs, compared by
  content with types (`"01"` vs `1` is a difference; `200` vs `200.0` is
  not); skips without `FIXTURES_PARIDAD`.
- Full suite, `ruff` and `mypy --strict` clean.

### Timings (direct `procesar`, this machine)

`validar` takes 0.03–0.11 s per file (headers only). `procesar`: AMEX 0.22 s,
DINNERS 3.7–3.9 s, MASTERCARD 0.20 s, SAFETYPAY 0.45 s, VISA 0.18–0.20 s,
IZIPAY 0.45 s, EFECTIVO 5.2–5.4 s. All seven in one execution: 11.4 s with a
peak RSS of 126 MB — inside the 60 s timeout and the 256 MB child budget.
Almost all of the time goes to iterating the formatted-empty rows of DINNERS
and EFECTIVO.

## Still open

- **DINNERS exceeds the 25 MB per-file cap** (50.7 MB; the whole batch is
  ~57 MB against a 25 MB total cap). With the default caps the real DINNERS
  file is rejected over HTTP with a 422 `tamano`. Either the contract row
  gets larger caps or the file is saved without its embedded drawings.
- **`columna_faltante` names the column, not the sheet.** Only `Fecha
  Cierre` is shared by both sheets of a workbook, so the ambiguity is small.
- **`tipo_duplicado` names only the second file**, not the type.
- **The script version is inferred.** The manifest's `version_script` is the
  hash of the script handed over with the outputs; exact parity is the
  evidence that it is the one that ran.
